# TermMan Local MCP Server 使用说明

## 概述

TermMan 提供了一个本地 MCP (Model Context Protocol) 服务器，为 LLM 提供终端操作能力。

## 架构

```
┌─────────────┐     ┌──────────────┐     ┌─────────────────┐
│    LLM      │────▶│  MCP Client  │────▶│  Local Server   │
│ (DeepSeek)  │     │ (server_mgr) │     │ (local_server)  │
└─────────────┘     └──────────────┘     └────────┬────────┘
                                                   │
                                          ┌────────┴────────┐
                                          │                 │
                                    ┌─────▼─────┐     ┌─────▼─────┐
                                    │  终端 SDK  │     │ LogManager│
                                    │ (命令执行) │     │ (日志读取)│
                                    └───────────┘     └───────────┘
```

## 可用工具

### 1. execute_command

在终端执行 shell 命令。

**参数：**
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| command | string | 是 | 要执行的命令 |
| item_id | string | 自动注入 | 目标终端 ID |

**示例调用：**
```json
{
  "name": "mcp_local_execute_command",
  "arguments": {
    "command": "ls -la"
  }
}
```

**返回值：**
```json
{
  "success": true,
  "result": [
    {"type": "text", "text": "Command sent: ls -la"}
  ]
}
```

**注意：** 命令是异步发送到终端执行的，需要使用 `read_terminal_log` 查看执行结果。

---

### 2. read_terminal_log

读取终端日志文件，获取命令执行结果。

**参数：**
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| lines | integer | 否 | 读取最后 N 行，默认 64 |
| item_id | string | 自动注入 | 目标终端 ID |

**示例调用：**
```json
{
  "name": "mcp_local_read_terminal_log",
  "arguments": {
    "lines": 20
  }
}
```

**返回值：**
```json
{
  "success": true,
  "result": [
    {
      "type": "text",
      "text": "=== 终端日志 (最后 20 行) ===\n[2026-03-30 04:30:00] total 32\n[2026-03-30 04:30:00] drwxr-xr-x  2 root root 4096 Mar 30 04:30 .\n..."
    }
  ]
}
```

---

### 3. read_file

读取文件内容。

**参数：**
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| file_path | string | 是 | 文件绝对路径 |

**示例调用：**
```json
{
  "name": "mcp_local_read_file",
  "arguments": {
    "file_path": "/app/backend/config.py"
  }
}
```

---

### 4. write_file

写入文件内容。

**参数：**
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| file_path | string | 是 | 文件绝对路径 |
| content | string | 是 | 文件内容 |

**示例调用：**
```json
{
  "name": "mcp_local_write_file",
  "arguments": {
    "file_path": "/app/backend/test.txt",
    "content": "Hello, World!"
  }
}
```

## item_id 自动注入机制

### 为什么需要自动注入？

每个终端会话有唯一的 `item_id` (UUID)，用于：
- 标识终端会话
- 关联日志文件 (`/app/backend/app/services/log/{item_id}.log`)
- 路由命令到正确的终端

### 自动注入流程

```
1. 前端请求: POST /api/v1/chat/{item_id}/stream
                    ↓
2. API 路由提取 item_id
                    ↓
3. LLM 决定调用工具 (可能不传 item_id 或传错误值)
                    ↓
4. 后端强制覆盖: tool_args["item_id"] = item_id
                    ↓
5. MCP 工具使用正确的 item_id 执行操作
```

### 代码实现

```python
# chat.py
@router.post("/{item_id}/stream")
async def chat_stream(item_id: str, ...):
    # item_id 从 URL 路径获取
    ...

# 工具调用时强制注入
tool_args["item_id"] = item_id  # 覆盖 LLM 可能传的错误值
```

## 典型使用场景

### 场景 1：诊断终端错误

```
用户: "终端报错了，帮我看看"

LLM 调用流程:
1. read_terminal_log(lines=50)  → 获取完整错误日志
2. 分析错误原因
3. execute_command("diagnostic_cmd")  → 执行诊断命令
4. read_terminal_log(lines=20)  → 查看诊断结果
5. 返回解决方案
```

### 场景 2：查看目录结构

```
用户: "当前目录有什么文件"

LLM 调用流程:
1. execute_command("ls -la")  → 列出文件
2. read_terminal_log(lines=30)  → 获取命令输出
3. 格式化返回给用户
```

### 场景 3：修复配置文件

```
用户: "配置文件有语法错误"

LLM 调用流程:
1. read_file("/app/config.yaml")  → 读取配置
2. 分析语法错误
3. write_file("/app/config.yaml", fixed_content)  → 写入修复后的配置
4. execute_command("service restart")  → 重启服务
5. read_terminal_log(lines=20)  → 确认修复成功
```

## 配置文件

MCP 服务器配置位于 `/app/backend/mcp_servers.json`：

```json
{
  "mcpServers": {
    "local": {
      "command": "python",
      "args": ["-m", "app.services.agent.mcp.local_server"],
      "env": {}
    }
  }
}
```

## 日志文件

终端输出日志存储位置：
```
/app/backend/app/services/log/{item_id}.log
```

日志特性：
- 最大 3MB，超出后自动清空
- 按时间戳记录每行输出
- 支持读取最后 N 行

## 错误处理

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| `No log found for {item_id}` | 日志文件不存在 | 等待终端产生输出 |
| `Command sent: xxx` | 命令已发送但结果未知 | 使用 read_terminal_log 查看结果 |
| `File not found: xxx` | 文件不存在 | 检查路径是否正确 |

## 最佳实践

1. **命令执行后立即读取日志**
   ```
   execute_command("pwd")
   → 等待 1-2 秒
   → read_terminal_log(lines=10)
   ```

2. **使用合理的日志行数**
   - 简单命令：10-20 行
   - 错误诊断：50-100 行
   - 完整日志：不指定 lines 参数

3. **文件操作使用绝对路径**
   ```
   ✅ /app/backend/config.py
   ❌ config.py (相对路径可能出错)
   ```

4. **多轮对话中检测循环**
   - 系统会自动检测同一工具重复调用 3 次以上
   - 触发后会终止对话并提示用户
